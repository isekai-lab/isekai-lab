# HD-2D実験室

3D背景と大型キャラクターの描画・制作方式を比較する独立した実験プロジェクトです。既存の短編ゲーム試作`3min-rpg/`と並べて、この`hd-2d/`で開発します。

Babylon.jsで森・街・洞窟の3D背景を比較する実験室です。共通の表示基盤を使う統合画面、マップ改善画面、固定コースで人物を動かす画面を分けています。キャラクターの表示方式の比較は、この歩行基盤の上に追加します。

詳細は[背景・大型キャラクター実験計画](../docs/hd2d-experiment-plan-2026-11.md)を参照してください。

## 方針

- 商用利用を含め無料で使えるツールに限定します。
- Babylon.js＋TypeScriptで共通実験基盤を作り、外部通信不要の単体HTMLへまとめます。
- 背景は2D配置データに高さ・形状を指定して立体化します。
- 同じボス原型を、部位別3D・事前レンダースプライトで比較します。2Dパーツ方式は必要に応じて追加します。
- 共通のカメラ・照明・動作時刻・アセット契約を固定した後、背景とキャラ各方式を並行開発します。
- ソース・型検査・ビルド処理・出力はこのディレクトリ内で管理します。依存バージョンはリポジトリルートの`package.json`とlockfileで固定し、配布物は`dist/`へ生成します。

## 表示の比較

画面上部の「ビュー」「マップ」「人物」で実験ページを切り替え、背景側では「街」「森」「洞窟」を選びます。表示調整パネルではズーム・視点、昼夕の照明、影、描画効果、軽量描画、演出の時間停止を変更します。スマホではパネルを畳んで背景を眺められます。

設定JSONを保存・復元して同じ条件へ戻せます。「初期化」は街と標準設定へ戻します。

テクスチャは石・木・草などの材質色と細部を描く新規の手続き的素材です。日差しや建物の方向性のある落ち影は焼き込まず、3Dのライトと影で付けます。素材の出自とライブラリの表示義務は[LICENSES.md](LICENSES.md)を参照してください。

## 実装の分担

- `src/common/`: カメラ・照明・設定・比較UI・計測。統合担当が所有。
- `src/contracts/`: 表示設定、マップ・通行面の共通契約。変更は統合担当が取りまとめる。
- `src/maps/`: 背景の配置・材質・立体生成、配置からの高さ問い合わせ。背景担当が所有。
- `src/characters/`: 見た目のアダプターと、見た目に依存しない移動処理。キャラ担当が所有。
- `src/fixtures/`: 背景改善から独立した、柱・階段・橋・水辺の固定検査コース。
- `src/entries/`: 3画面の薄い起動処理。
- `scripts/`: 単体HTMLビルドとローカル配信。`tests/`: 通行面・設定・計測・配布物の検証。

「人物」では仮人形を矢印キー／WASD、または地面のクリック・タッチで移動します。経路探索はせず、障害物や通れない水辺で止まります。人形の足元が原点、高さ1が共通の物差しです。スプライト・GLBの本格的な方式比較は後続です。

## 計測と反復改善

「2秒+10秒計測」は選択したマップと標準／軽量品質を保ち、基準カメラ・光・静止時刻0へ戻します。シェーダー準備完了後、2秒ウォームアップして10秒測ります。設定・マップ・画面寸法・タブの表示状態が変わると中止します。完了後に条件を変えた場合も結果を無効化します。

「結果JSON」にはソース内容ID、プリセット版、HTMLバイト数、CSS／描画寸法、DPR、設定、カメラ、フレーム間隔とCPU描画時間のp50/p95、描画回数などを保存します。CPU時間はGPU時間ではありません。「シーンPNG」はブラウザの枠やUIを含まない描画を保存します。人物の固定コースはマップ6条件の計測対象外です。

見た目の評価仕様は[計画書のベンチマーク](../docs/hd2d-experiment-plan-2026-11.md#12-森街洞窟の反復改善ベンチマーク)にあります。変更前後を同じ条件で保存し、共通処理の変更では3マップと縦画面を確認します。画像と計測の記録は`results/`へ置きます。古い版のライブFPS表示を、計測結果として扱わないでください。

## ビルドと非公開デプロイ

リポジトリのルートで実行します。

```sh
npm run hd2d:build
npm run hd2d:preview
npm run hd2d:typecheck
npm run hd2d:test
npm run cf:check
npm run cf:with-env -- npm run cf:deploy:private
```

`hd2d:build`はこのプロジェクトだけをビルドし、`hd-2d/dist/`へ`index.html`・`maps.html`・`characters.html`を生成します。エンジン・シェーダー・素材の生成処理・UIを内包し、実行時にCDNや外部画像へ接続しません。ルートの`npm run build`は従来どおり`3min-rpg/`用です。

`npm run hd2d:preview`は`http://127.0.0.1:4310/`で3画面を配信します。必要なら`PORT=4311 npm run hd2d:preview`のように別ポートを使えます。

`npm run hd2d:build -- --page maps`または`--page characters`は指定ページだけを更新し、他ページを保持します。同時ビルドは`.build.lock`で拒否し、全出力の生成後に置き換えます。実行中のビルドがないことを確認せずにlockを消さないでください。共通コードを変えたら全画面を再ビルドします。

`cf:check`は両プロジェクトのビルドと検証、Cloudflare配布用HTMLの集約を行います。`cf:deploy:private`は検証後、既存のゲームとHD-2D実験を一緒に更新します。認証情報とTerraformの準備は[CloudflareのREADME](../infra/cloudflare/README.md)を参照してください。

配信先は既存の本人専用環境の[/hd-2d/](https://tensei-private-games.tensei-lab.workers.dev/hd-2d/)です。登録したサークル用メールに届くワンタイムコードでログインします。背景は同じURL配下の`maps.html`、人物は`characters.html`です。配信は1担当が両方の変更を取りまとめて行い、別worktreeからそれぞれ本番を上書きしません。プレビューURLは無効にし、このパスにも既存のAccess認証とWorkerのJWT検証を適用します。

ビルド後は`hd-2d/dist/index.html`をPCのブラウザで直接開いて実験できます。スマホでは上記Cloudflare URLを利用します。WebGLに対応したブラウザが必要です。将来追加する実験も、このディレクトリの`dist/`直下へ自己完結したHTMLとして出力します。
